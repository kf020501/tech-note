DynamoDB(NoSQL)とRDBの使い分け
================================================================================

[CQRS パターン - AWS 規範ガイダンス](https://docs.aws.amazon.com/ja_jp/prescriptive-guidance/latest/modernization-data-persistence/cqrs-pattern.html)

以下、ChatGPTに質問した

---

NoSQL（DynamoDBなど）とRDBMS（MySQL, PostgreSQLなど）の使い分けは、データの性質やシステムの要件によって決まります。以下、具体的な例を挙げながら説明します。

**1. RDBMS（リレーショナルデータベース）の適用例**
--------------------------------------------------------------------------------

### **特徴**
- **スキーマが固定**（テーブル構造が事前に決まっている）
- **ACID（Atomicity, Consistency, Isolation, Durability）を保証**
- **複雑なクエリが得意**（JOIN, トランザクション管理）

### **利用例①：ECサイトの受注管理**
- **データ構造**
  - 顧客情報（顧客ID, 氏名, 住所, メールアドレス, 購入履歴）
  - 注文情報（注文ID, 顧客ID, 商品ID, 注文日時, 状態）
  - 商品情報（商品ID, 商品名, 在庫数, 価格）

- **理由**
  - 顧客と注文の **リレーション（関係性）** を考慮する必要がある
  - **トランザクションが重要**
    - 例：「カートに入れたが決済されなかった商品」を適切に管理する必要がある
  - **JOINを使ってデータを統合**（例：「ある顧客の購入履歴を取得」）

---

**2. NoSQL（DynamoDBなど）の適用例**
--------------------------------------------------------------------------------

### **特徴**
- **スキーマレス**（柔軟なデータ構造）
- **水平スケールしやすい**（データ量が増えても処理を分散しやすい）
- **高い可用性と低レイテンシー**

### **利用例②：IoTデバイスのセンサーログ管理**
- **データ構造**
  - IoTデバイスID（パーティションキー）
  - 記録時刻（ソートキー）
  - 温度, 湿度, 気圧, バッテリー残量 など

- **理由**
  - **大量の書き込みに強い**
    - センサーデータは継続的に送られ、大量のログが発生する
  - **スキーマ変更が柔軟**
    - 追加のセンサーを導入して新しいデータ項目が増えても対応可能
  - **アクセスパターンが単純**
    - 例：「特定デバイスの最新100件のログを取得」

---

**3. どちらを選ぶべきか？**
--------------------------------------------------------------------------------

| 要件                                       | RDBMS | NoSQL         |
| ------------------------------------------ | ----- | ------------- |
| データの関係性（リレーション）が強い       | ○     | ×             |
| データの整合性（ACID）が重要               | ○     | △（一部対応） |
| スキーマが明確に決まっている               | ○     | ×             |
| 高速な書き込みが必要（リアルタイムデータ） | △     | ○             |
| スケールアウトが必要（大規模アクセス）     | △     | ○             |
| クエリが複雑（JOIN, 集計など）             | ○     | △             |

---

**4. ハイブリッド構成の例**
--------------------------------------------------------------------------------

最近では、RDBMSとNoSQLを組み合わせるケースもあります。

### **例③：ソーシャルメディア（Twitterのようなアプリ）**
- **ユーザー情報・フォロワーデータ（RDBMS）**
  - ユーザーID, 名前, メールアドレス
  - フォロワー関係（ユーザーAがユーザーBをフォロー）

- **投稿データ（NoSQL, DynamoDB）**
  - 投稿ID, ユーザーID, テキスト, タイムスタンプ, いいね数
  - 最近の投稿を取得するためのクエリが速い
  - 高頻度の書き込みを処理可能

---

### **結論**
- **データの整合性やリレーションが重要** → **RDBMS**
- **高スループット・スケール性・リアルタイム性が重要** → **NoSQL**
- **両方のメリットを活かす** → **ハイブリッド構成（用途に応じて使い分け）**

DynamoDBはECサイトの「商品在庫キャッシュ」などに使われることもあり、RDBMSと補完的に利用することが増えています。
